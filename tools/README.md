# キレイン 営業ツール

## prospect.mjs — 見込み店 抽出エンジン
指定エリアの飲食店をGoogle Placesで探し、**公開口コミに「清潔ネガ」が付いた店だけ**を抽出。
店ごとに“当てフック文面”＋無料診断URLを生成して CSV / JSON で出力する。
＝キレインの監視エンジンを、そのまま**見込み客発掘マシン**に転用する道具。

### 動作確認（鍵なし・サンプルデータ）
```bash
node tools/prospect.mjs --mock
```

### 本番（実データ）
```bash
PLACES_KEY=＜Places APIキー＞ node tools/prospect.mjs --area "難波 居酒屋" --limit 40 --out osaka_namba
```
- `--area`   検索クエリ（例: `"天神 居酒屋"` `"すすきの 焼肉"` `"栄 バル"`）。エリア×業種で絞ると精度が上がる。
- `--limit`  取得する候補店の上限（既定40）。
- `--out`    出力ファイル名の接頭辞（`<out>.csv` と `<out>.json`）。
- `--diag`   診断URLのベース（既定 `https://kirein.net/diagnose.html`）。

出力例（`osaka_namba.csv`）: 順位 / 店名 / 住所 / 評価 / 口コミ数 / 検知エリア / ネガ件数 / 診断URL / フック文面
→ **清潔クレームが強い店ほど上位**。上から順に手で当てていく。

### PLACES_KEY について
- Node実行なので **HTTPリファラー制限なしのサーバー用キー** が必要（Workerの `GOOGLE_PLACES_KEY` と同種）。
- `diagnose.html` に載っているブラウザ用キー（kirein.net制限あり）は**使えない**。
- Google Cloud Console → 認証情報 で、Places API 有効・アプリケーション制限なし（またはIP制限）のキーを1本。

### コスト目安
- 40店スキャン ≒ Place Details（口コミ付き）40回＋Text Search 1〜3回 ≒ **$1〜2/回**。
- Googleの月$200無料枠内で、毎日数エリア回しても当面おさまる。

### ⚠️ 運用の作法（守る）
- **冷たいDMに Google口コミを丸引用しない**（帰属義務・ToS）。フックは「エリア名の要約」だけ。
  生の引用・詳細は、相手が **無料診断(diagnose.html)** に来てから見せる。
- **送信は人間が1件ずつ**。文面には送信者明示＋オプトアウトを同梱済み（特定電子メール法の衛生）。
  SNS（Instagram/LINE）の**自動一斉DMはやらない**（ToS違反＝アカウント凍結）。まずは郵送DM・問い合わせフォーム・電話。
- 抽出リストは**営業のための一時作業データ**。長期保管・再配布はしない。
- 公開口コミは Place Details の上位5件が対象＝「目立つ清潔クレーム」を拾う設計（＝いちばん店を痛めてる声＝いちばん刺さる）。
- 公開営業の前に **弁護士ゲート（景表法・ステマ規制）** を1回通す。

### funnel（型）
```
prospect.mjs で抽出 → 店ごとの当てDM（フック文面＋診断URL）
        ↓
diagnose.html?s=<place_id> で“その店の”清潔リスク診断を即表示
        ↓
見張りプラン ¥3,000/月（start.html → Stripe）
```
